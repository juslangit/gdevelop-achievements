01-idea.md · 0 sections

The idea

Idea #8 of the GDevelop extension list made 2026-11-16 (Idea Vault 874). The store has no general achievements extension (only Game Jolt and Wortal ones), and every game wants them.

Luqman's choices (2026-11-16): one "Define achievement" action per achievement; a built-in restyleable toast; no built-in achievements screen (expressions only, the example shows one); ship to the store via PR after he tries it.

04-methods.md · 0 sections

Methods

  • Extension free-function instructions take a hidden first AND last parameter: ["", ...params, ""].
  • GDevelop "key just pressed" misses Playwright press; hold keys ~60 ms in tests.
  • Tools copied from gdevelop-year3 tap-dash (gdenv/loader/build_html5/play.js + vendored libGD); node_modules is node_modules.nosync + symlink so iCloud doesn't sync it.
  • Opening in GDevelop: open -a "GDevelop 5" --args "<path>/Achievements Example.json" (GDevelop must be closed).

06-decisions.md · 0 sections

Decisions

DateDecisionWhy
2026-11-16Runtime core in JavaScript (src/core.js), thin JS events per functionToast drawing and storage are far simpler and safer in JS than in events; store accepts JS extensions
2026-11-16Toast drawn on its own runtime layer __AchievementsToast, kept lastIn games with a 3D renderer GDevelop renders each layer separately, so a child of the scene container would never show
2026-11-16Save in localStorage key GDJS_Achievements_<game name>Works in web/desktop/mobile; game name avoids clashes on shared origins like gd.games
2026-11-16"Just unlocked" is true for the whole next frame (pending → just in onScenePreEvents)Works wherever the condition sits in the event sheet, exactly once
2026-11-16PIXI v7/v8 feature-detectedSafe across GDevelop versions
